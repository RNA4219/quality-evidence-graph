## 3. 指摘一覧

| ID | Severity | 指摘 | 対応 |
|---|---|---|---|
| FIND-01 | medium | `human review または waiver が残る場合は conditional_go 以上には上げない` は severity の向きが曖昧。 | `go` にせず、判定資格が成立していれば `conditional_go` に留める、と修正。 |

## 4. 修正方針

- 要求正本に反する仕様変更は行わない。
- 仕様本文の修正は、実装者が型、schema、fixture、Gate evaluator へ写像するときに迷う箇所だけに限定する。
- release Go 条件は緩和しない。
- DQ、waiver、approval evidence、retention、immutability の統制は `ipo_controlled` 側へ寄せ、MVP の release Go と混同しない。

## 5. Gate 判定

- 仕様書 review Gate: `go`
- 実装着手 Gate: `go`
- IPO controlled release Gate: `no_go`

理由:

- Gate policy、waiver、approval evidence、evidence package、retention、immutability、職務分掌は実装仕様として追跡可能になった。
- DQ 最優先、waiver で DQ を消せない、`conditional_go` exit code `2` は要求正本と仕様書群で整合している。
- ただし、TypeScript 型、JSON Schema、CLI、fixture 実体、own-output validation、実証済み evidence package は未実装である。
