# Quality Evidence Graph v0.3.1

v0.3.1は、npm registryを運用境界から外し、GitHub Releaseと自己完結したGitHub Actionを正規の配布経路にするpatch releaseである。graph wire contractは引き続き `qegVersion=0.2` とする。

## 変更点

- `qeg-report-action`へNode.js 20以上で実行できるCLI bundleを同梱した。
- Actionの既定実行は公開npm packageや `npx` に依存しない。
- packageは `private: true` とし、誤ったnpm publishを防止した。
- Linux Node.js 20/24に加え、Windows Node.js 24のportability jobを追加した。
- release lifecycle acceptanceを追加し、変更、リスク、テスト、隔離デプロイ、観測、意図的障害、復旧、新しい証拠生成を一続きで検証する。
- hash-backed fixtureの改行コードを固定し、Windows checkoutでもartifact SHA-256を再現可能にした。

## 利用方法

GitHub Actionはtagへ直接固定する。

```yaml
- uses: RNA4219/quality-evidence-graph/qeg-report-action@v0.3.1
  with:
    targets: .qeg
```

CLIが必要な場合はGitHub Release添付のtarballを取得し、検証済みのcommit/tagとSHA-256を対応づけて使用する。npm registryへの公開・installはv0.3.1の配布契約に含めない。

## ライフサイクル受入

`npm run test:release-lifecycle` は次を実行する。

1. v0.3.1 bundleを隔離release directoryへ配置する。
2. fresh consumerへ `qeg init` する。
3. version、schema、positive reportを観測する。
4. 配置済みschemaを意図的に破損させ、schema-checkがexit 1になることを観測する。
5.同一bundleからschemaを復元する。
6. schema-checkとreportがexit 0へ戻ることを確認する。
7. before/fault/recovered reportと、各ファイルのSHA-256を含むlifecycle evidenceを新規生成する。

これはAction/CLI配布物の回復可能性を実証する。実clusterへのdeployment、実fault injection、対象サービス自体のresilience承認は別の受入境界である。

## 互換性

Reliability / Resilience、DQ-18〜DQ-21、BLK-REL-01〜04、normalizer、fail-closedな `evidenced_by` provenance検証を含むv0.3.0 contractを維持する。Actionの `report-command` overrideも互換用に残す。
